## Confirmed passenger speech scope

The complete implementation is in [reactions.rs](../crates/omsi-sim/src/people/reactions.rs), invoked from [pax_tick.rs](../crates/omsi-sim/src/people/pax_tick.rs). [pax_task.rs](../crates/omsi-sim/src/people/pax_task.rs) calls `thank_on_exit` when a local rider actually leaves the player's bus.

- Closed-door request: waits near this bus's door/platform while stopped, then searches installed voice variants. A localized `BridgeOpenDoor` caption is available even when there is no dedicated voice file. It does not include or synthesize a new recording.
- Missed stop / closed-on-rider reaction: tracks the wait and subsequent departure. Anger lines use the installed pack. Current caption selection still uses `BridgeOpenDoor`, including this case; it is not a distinct missed-stop subtitle.
- Thanks when leaving: `Thanks_1`, with a 22% selection chance; actual playback is subject to the normal voice setting and shared audio cooldown. Ordinary payment thanks already existed in the upstream `pax_driver.rs` and must not be credited as a new Hotfix 2 feature.
- Bad-driving complaints: the upstream implementation remains in [pax_driver.rs](../crates/omsi-sim/src/people/pax_driver.rs). The door/missed-stop additions supplement it; they do not replace it.

## Existing safeguards actually present

- The capture reader runs on a worker at 250 ms, limits individual reads to 64 KiB and checks schema, process id and timestamp freshness. Its tests include interrupted JSON, ambiguity and stale data. This avoids file scanning directly in the render loop; per-frame processing costs above still remain.
- Responders use per-instance roles instead of converting every matching civilian model into police/fire traffic. Physical arrival checks use actual position, height and speed. Departure/retirement is distinct from BCS completion; a BCS delay alone cannot establish arrival.
- Stop tolerance tests reject opposite-road, different-floor and far-stop examples. The new exit check requires an actual animation value above 0.90 rather than a keypress alone. This is useful coverage, not universal cabin-map proof.
- Inspector paths preserve the reserved seat, prefer physically reachable aisle targets and include retry timers when the return path is disconnected. The index-only patrol test does not prove every live cabin path works.
- Temporary source reconstruction and file-disjoint patch verification are automated by `verify.py`. That protects the delivery from missing source files and overlapping extraction patches; it is not a runtime test.

## Integration approach that avoids repeating the earlier PR mistakes

1. Start from current upstream main and inventory already merged passenger helpers. Do not apply this historical 0.3.46 series as if main were unchanged. The exact-series patches are reference material.
2. Share common settings/catalog and integration changes once. For actual upstream submissions, split independently reviewable/compilable commits and test files by feature, stack dependent inspector/incident work explicitly and keep the complete root source available for context.
3. Preserve the read-only nature of cosmetic gestures; do not consume task RNG or rewrite boarding intent when the optional feature is disabled. The BCS companion genuinely changes a medical passenger's native state, so describe that distinction and keep BCS business counters untouched.
4. Preserve host authority and existing protocol constraints. Do not copy the single-player-only approval of #3429 onto this cooperative passenger/incident implementation. Verify duplicate messages, stale events, map changes and two-PC ownership transitions separately.
5. Complete all new translations, persist both settings writers, keep tests in per-feature modules and actually run them in CI. Existing successful PR builds belong to those PR heads, not automatically to this export.
6. Profile comparable before/after builds at the same populated stop and long avenue: same traffic, passengers, camera, weather, GPU settings and save. Record median/p95/p99 frame time, simulation/people/renderer time, allocations, RAM and dedicated/shared GPU memory. Test absent/disabled/active events and separated LAN centers. Do not lower graphics to disguise a source regression.

No original OMSI asset or BCS proprietary JAR is required in this source package. Existing upstream and data-file licenses are retained; approval of another port does not grant a new license to the whole workspace.
