# OpenOMSI BCS Bridge 2.1.9.7 hotfix 1

## Português

Corrige a detecção de **Próxima viagem** no BCS atual. A extensão de log anterior consultava uma função interna ofuscada que passou a indicar uma avaria do ônibus. Com esse indicador desativado, a seleção seguinte não chegava à Bridge e a tentativa direta do BCS era recusada pelo openOMSI em multiplayer, que exige atribuição pelo host.

A atualização corrige também extensões já instaladas: o Setup e o atualizador aplicam o reparo com o BCS fechado. A seleção aceita continua exigindo modo multiplayer, identificador válido, mapa e viagem. A troca utiliza o pedido e a confirmação do host, com verificação da tabela, do letreiro e preservação da avaliação anterior.

A opção **Ligar o ônibus automaticamente** mantém o valor salvo, incluindo iniciar com o ônibus desligado. Combustível, empresa, convite, preferências, idiomas PT-BR/EN/DE e transferências de ônibus/pinturas da 2.1.9.7 continuam disponíveis. O instalador preserva as configurações e faz uma cópia recuperável do JAR local antes de corrigir somente nossa extensão. Nenhum JAR do BCS é distribuído.

**Instalação:** feche BCS, openOMSI, Setup, HostAgent e CompanyHost. Use **Buscar atualizações** no Setup ou execute `Atualizar-Bridge.exe`; depois reabra o HostAgent e o BCS. Não é necessário reinstalar a Bridge. Identificação interna: `2.1.9.7-hotfix.1`, publicação `2026101802`.

## English

Fixes **Next trip** detection with the current BCS. The earlier logging extension consulted an obfuscated internal API that now represents vehicle damage. When that flag was false, the next selection was not exposed to the Bridge; BCS's direct duty request was rejected by openOMSI multiplayer, where the host assigns duties.

Setup and the cumulative updater repair already installed observers while BCS is closed. Accepted continuations still require multiplayer mode, a valid shift, map and trip. Host dispatch and acknowledgment, timetable/destination checks and previous evaluation retention remain active.

The saved **Start the bus automatically** preference is retained, including manual engine startup. Fuel, company, invitation, preferences, PT-BR/EN/DE and 2.1.9.7 bus/livery transfers are preserved. The local JAR is backed up before changing only our logging extension. No BCS JAR is distributed.

**Installation:** close BCS, openOMSI, Setup, HostAgent and CompanyHost. Use **Check for updates** in Setup or run `Atualizar-Bridge.exe`, then reopen HostAgent and BCS. Reinstallation is unnecessary. Internal version: `2.1.9.7-hotfix.1`; publication `2026101802`.

## Deutsch

Korrigiert die Erkennung von **Nächste Fahrt** mit dem aktuellen BBS. Die bisherige Protokollerweiterung fragte eine verschleierte interne Funktion ab, die inzwischen einen Fahrzeugschaden bezeichnet. Ohne diesen Zustand erhielt die Bridge keine neue Auswahl. Der direkte Fahrtauftrag von BBS wurde im openOMSI-Multiplayer abgelehnt, da der Host die Dienste zuweist.

Setup und das kumulative Update reparieren bereits installierte Erweiterungen bei geschlossenem BBS. Eine akzeptierte Auswahl erfordert weiterhin Multiplayer-Modus, gültige Schicht, Karte und Fahrt. Host-Zuweisung und Bestätigung, Fahrplan-/Zielprüfung und die vorherige Auswertung bleiben erhalten.

Die gespeicherte Einstellung **Bus automatisch starten** bleibt erhalten, einschließlich manuellem Motorstart. Kraftstoff, Firma, Einladung, Einstellungen, PT-BR/EN/DE und Bus-/Lackierungsübertragungen aus 2.1.9.7 bleiben verfügbar. Vor der Reparatur ausschließlich unserer Protokollerweiterung wird die lokale JAR gesichert. Es wird keine BBS-JAR verteilt.

**Installation:** BBS, openOMSI, Setup, HostAgent und CompanyHost schließen. In Setup **Nach Updates suchen** oder `Atualizar-Bridge.exe` ausführen, danach HostAgent und BBS öffnen. Keine Neuinstallation nötig. Interne Version: `2.1.9.7-hotfix.1`; Veröffentlichung `2026101802`.

## Validation scope

The old observer reproduces the missing continuation with a false damage flag. A verifying JVM exercises the repaired helper and actual logger entry, normal/event continuations, incomplete selections and unrelated messages. Tests cover upgrading an installed observer, preserving all other archive entries, exact backups, repeat installation, malformed helpers and class truncation. A local check also uses the supplied current JAR with synthetic state APIs; proprietary code is not committed. Existing Go/Lua/gateway and Windows checks cover manual engine startup, fuel, evaluation rebasing, destination confirmation and native 0.3.38/0.3.37 transfer compatibility. A complete real BCS next-trip session remains a player validation step.
