# Live next trip for the 2.1 native adapter

When BCS completes a shift and selects another complete shift on the same map,
vehicle and HOF, the adapter can update the running game's duty. It waits for a
stable selection, asks a private Lua companion to resolve exactly one timetable
trip, saves the previous simulator counters, captures the new BCS baseline and
applies the new duty. Cumulative simulator counters are rebased using actual
deltas; the completed shift remains frozen until the change is confirmed.

The 0.2.29 plugin API was inspected. For a local game, `duty.start` uses the
simulator's own timetable, IBIS and timetable-paper update. For a multiplayer
client, the companion sends a request through its existing authenticated LAN
peer. HostAgent 2.1.1-host.2 translates only that peer's own duty request into a
loopback native `/admin` dispatch, keeps the administration password private,
and relays the matching `duty-ok` acknowledgment. Actual duty and destination
state are still checked by the companion. The company clock is not changed.

The adapter mirrors stable changes to PeDePe's generated `bbs.lua`, preserving
its contents and allowing the native loader to reload updated telemetry.

Changed map, vehicle/HOF, ambiguous trip, moving vehicle, rejected dispatch and
unconfirmed transitions do not trigger an automatic game/server shutdown.
If a timetable changes but the HOF destination cannot be verified, the player
receives a warning instead of a false success notification.

## Small updates

Player ZIP: `Setup.exe`, `PeDePeAdapter/openomsi.exe`, its patch checksum list
and instructions. Host ZIP: `Setup.exe`, `HostAgent.exe`, its patch checksum
list and instructions. These are overlays for an existing 2.1 installation;
they contain no user configuration, company profile or official simulator.
The new Setup preserves the base package's integrity checks and merges only
the separately attested executable replacements. Apply the host update first
for multiplayer. Install each ZIP into the existing package directory.

## Validation

Targeted Go regressions passed with race detection: selection/completion
identity, stable preparation and confirmation, real personnel counter deltas,
host peer ownership, command injection rejection, native acknowledgment relay,
and base/patch integrity. The actual Lua companion was exercised against the
documented 0.2.29 API shape for local and multiplayer transitions, ambiguity,
cancellation and a changed vehicle. Windows x86 builds and static checks
passed; the existing Win32 unsafe-pointer boundary was excluded as in the
preceding host build. Real BCS/OpenOMSI operation on Windows remains to be
validated by a test session.
