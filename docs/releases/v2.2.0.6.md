# Bridge 2.2.0.6 / Coop12

The game and the managed dedicated server now use the complete cumulative
Coop implementation on openOMSI 0.3.40, protocol 15. This is a source merge
onto pinned upstream `e874276e1bfa22896deb1e00adab0ed7d4f3ce2f`, preserving
native driver state transfer, BCS ownership, conductor transactions, picking,
characters, F1 visibility, destination and livery changes, and world interest
around both walkers and buses. Protocol 15 traffic compression and voice remain
present. Handover uses its own packet discriminator, separate from traffic and
voice, with real-socket relay/authentication regression coverage.

Dedicated `/status.world` is published only after the initial simulation frames
finish, including cold traffic/passenger spawning. An accepted clock change
refreshes status immediately, without waiting for the periodic status tick.
The original full P15 HostAgent and CompanyHost binaries are retained byte for
byte; voice, radio, administration, map limits and other opaque preferences are
preserved. Known installation-managed P14 host selections and the bundled
client path migrate together to P15 with backups. Independently selected custom
servers remain deliberate selections. The legacy P14 runtime remains available
for separate older sessions.

One authenticated AI greeting event now plays two 170 ms taps of the model's
own horn, separated by 140 ms of silence, with short fades to avoid clicks.
Local and remote listeners use the same audio path; greeting cooldown and the
independent flash event are unchanged.

Setup polls all configured maps, shows every online map with a copy button,
and provides pagination when more than three maps are active. It copies the
current game join address, rather than a company profile or administrative
credential. Offline, starting and expired entries have no copy action. The
existing five-second timer and manual check remain available. PT, EN and DE
are supported. Native Windows GUI checks exercise the buttons, pagination,
UTF-16 clipboard, and removal of stale actions.

Install on the host and every participant. Protocol 14 and 15 cannot share one
session. Automated tests and native Windows checks are release prerequisites;
they do not certify a graphical two-player trip or BCS payment/evaluation.
