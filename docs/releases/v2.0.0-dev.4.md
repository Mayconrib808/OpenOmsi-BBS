# OpenOmsi + BBS 2.0.0-dev.4

A real company trip was blocked by a profile whose recorded hashes differed from 12 installed files, plus the dedicated server's startup clock while its map was still loading.

This build adds a controlled administrator update for an existing local profile: Setup **9 → 2**. It displays changed paths, updates only already declared file hashes, preserves company identity, packages, links, fleet paths, sessions and clock, and creates an exact backup of the previous JSON. Missing files or an expanded inventory are refused. Joining players never update the reference automatically; script and calendar differences remain checked.

Company-clock trips require the dedicated server's active world. A gateway still reporting `world:null` now tells the player to wait for **SINCRONIZADO** in CompanyHost. Fixed-date player-hosted sessions remain supported without dedicated world counts.

## Reuse the current installation

1. Close BCS and CompanyHost.
2. Extract the new complete package, configure its folders and select the existing profile in Setup option 8; activate/update with option 2.
3. Choose **9 → 2**, select the administrator's existing JSON, review the changed files and confirm the current installed content as the new reference.
4. Start the new CompanyHost using that same JSON and wait for **SINCRONIZADO**.
5. Open BCS and start the trip normally. Local testing on the server PC continues to use `http://127.0.0.1:27025`.

Share the updated profile with other players. This action does not install addons or normalize unknown BCS modifications. If BCS changes scripts or the calendar again on the next launch, preserve the new requirements report for comparison; repeated mutation needs its own diagnosis. Real BCS trip evaluation, boarding and two-player rendering remain pending.
