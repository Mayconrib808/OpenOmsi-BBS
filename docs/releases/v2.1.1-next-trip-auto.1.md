# Automatic next-trip Bridge update

BCS accepts an event/normal multiplayer continuation but logs only `Weitere Event Tour Multiplayer` or `Weitere Tour Multiplayer`. The Bridge consequently keeps the completed shift and receives no new selected shift/map/tour. The update automatically prepares those log fields from BCS's actual accepted selection.

`Atualizar-Bridge.exe` reads the BCS native selection from `config.cfg`: OMSI root at index 0, selected openOMSI/PeDePeAdapter folder at index 49, and native-mode choice at index 50. It locates OMSI from the saved Bridge preferences or Steam's existing libraries, including another drive, and follows the BCS `gad.txt` settings-directory redirect when present. ISO-8859-15 settings and UTF-16 launch logs are supported. The package's own configuration must match that OMSI root. Native players do not need the old Setup activation or Windows debugger interception; an old registry entry is used only as a compatibility fallback. Explicit saved BCS settings take precedence over old launch logs and registry entries.

The updater replaces only Setup and PeDePeAdapter, updates their component checksums, and prepares the local BCS communication method with an original-file backup. Players close BCS/openOMSI, execute this updater, and open BCS normally. No JAR selection, installation-folder choice, company enrollment or BCS-path change is required for an already configured native installation.

The normal Setup activation now includes the same automatic preparation. The native host remains `2.1.1-host.2`. The update preserves the company/profile configuration, host executable, and existing host manifest; its shared Setup checksum is updated to avoid conflicting player/host patch manifests.

The BCS archive and logger are guarded by exact inspected hashes. Only copy ranges and the added observational bytecode are included as a delta; no vendor JAR or vendor class is stored in the repository. Other/ambiguous installations and unsupported BCS builds are preserved. Existing installations of the separate logger fix are recognized. The updater rejects a busy vendor archive and known BCS Java processes, and never terminates a process.

Build locally with Go 1.23.2 and the package's resource assets:

```
python scripts/build_bridge_update.py --go /path/to/go --output /path/to/update.zip
```

The source-only delta can be reproduced from the exact inspected local BCS build with `scripts/build_bcs_trip_log_patch.py --emit-auto-delta source/bcs_trip_auto_payload.go`, alongside its required JAR and output arguments. The JVM fixture verifies the actual patched logger entry and its fallbacks with `-Xverify:all`.

Validation covers native discovery without registry activation, stale foreign registry entries, preferred user configuration, secondary Steam libraries, redirected settings, accented paths, bounded large Unicode log tails, preservation of unsupported versions, exact original backup, full archive integrity, repeated runs, host/player checksum combinations, and rollback when the full vendor archive differs. The executables compile for Windows x86. Actual Windows UI/UAC execution and the complete BCS → native timetable/IBIS handoff still require an in-game test before broad distribution.
