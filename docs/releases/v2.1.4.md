# 2.1.4

Fixes the Windows update handoff and subsequent Setup reopening. The previous
GUI called os.StartProcess with no standard handles, which Go rejects with
EINVAL on Windows before creating the child process. A shared launcher now
uses exec.Command to provide valid NUL handles and preserve argument escaping,
then releases its process handle after successful launch.

The Windows x86 candidate job now launches a real child process using a copied
executable in a directory with spaces and checks its marker argument. The Setup
GUI smoke check remains enabled. The regression applies to both update launching
and Setup reopening, which share the same process launcher.

All 2.1.3 native activation/status corrections and 2.1.2 next-trip fixes remain.
The affected 2.1.2/2.1.3 update button cannot install its own fix: install this
release once using the standalone updater with Setup closed or the manual ZIP.
Subsequent updates can use the corrected Setup button.
