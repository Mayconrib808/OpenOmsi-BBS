# Original 3D BCS emergency vehicle assets — candidate for Hotfix 2

Use: \`python scripts/build_bcs_real_vehicles.py --root native/bcs-assets\`

Generates **real 3D meshes** (OBJ/MTL), not billboard stand-ins:

- \`Vehicles/OpenOMSI_BCS/Police/Police.ovh\`: patrol sedan with 3D wheels, windshield, body, headlights and roof lightbar.
- \`Vehicles/OpenOMSI_BCS/Fire/Fire.ovh\`: fire appliance with actual 3D cab, wheels, lockers, pump and roof ladder.

The modified openOMSI supports OBJ input via \`omsi-o3d\` and has these exact fallback paths in \`crates/omsi-app/src/bcs_events/assets.rs\`. The loader always prefers a specifically configured installed emergency vehicle, then the bundled original 3D assets.

**Do not alter the published 2.2.2.1 Hotfix 1 immutable bundle.** For the **next version**:
1. Create a new separately versioned Windows client and P15 server candidate from the revised native source (PR #34), with explicit native source SHA and checks.
2. Rebuild \`native/bcs-assets\` using this script before calculating the distribution SHA-256. Delete legacy fallback asset directories first so prior cardboard meshes cannot accidentally remain.
3. Ensure the same generated files ship beside both \`openomsi.exe\` binaries; update the cumulative inventory and allowlist to include these new assets.
4. Run a Windows game test including no installed third-party emergency mods and BCS fire + police calls; confirm model appearance, wheel behavior, sirens, service completion, multiplayer and absence of regressions before publishing.
5. Only then sign and publish a new cumulative release via the existing Cloudflare updater. Do not reuse the Hotfix 1 version/sequence or silently overwrite historical artifacts.

No commercial OMSI models or addon content are embedded. These geometries are original and dedicated under CC0-1.0. They are a functional test candidate, not a claim of photorealism.
