# Next-trip native acknowledgment fix

The player adapter revision is `native-live-next-trip-3`. The user-facing update
remains one `Atualizar-Bridge.exe`, applied to the existing BCS-selected
PeDePeAdapter installation with BCS, openOMSI and Setup closed. Host.2 can remain
running; this update does not replace HostAgent or require another activation.

## Trigger and resulting behavior

On a multiplayer continuation from line 2002 to 4315, tour SAB01, departure
12:45, the native server accepted the administration request with HTTP 202,
assigned the duty and updated the IBIS/destination. Host.2 expected HTTP 200
and sent `Native dispatch rejected` before relaying the client's `duty-ok`.
The companion aborted on the first message, leaving the completed-trip
evaluation frozen even though the simulator had changed timetable.

The companion now keeps submission failures pending until the bounded native
confirmation timeout. The exact request's host acknowledgment and actual
matching timetable are both required. Line, tour, trip, departure, map and bus
checks remain in place; destination confirmation is still reported separately.
This permits the corrected player to work with the existing Host.2 in either
message order. A native `duty-no`, invalid request or selection conflict remains
a failure. Confirmed requests are not resubmitted, terminal LAN replies are
ignored and repeated cancel files preserve the first error without repeating
the on-screen warning.

The gateway source also now expects HTTP 202 for `/admin`, matching the native
0.2.30 `omsi-net/src/ws.rs` API. This source change will be included when a host
binary is built; the supplied player updater does not install a new host.

## Validation

- The new Carrão 4315/SAB01 regression failed against the previous companion
  under the actual Lua 5.4 runtime, reproducing the early abort.
- Registered LAN event tests cover rejection-before-ack, ack-before-rejection,
  native timetable and destination confirmation, delayed signs, missing
  acknowledgment, wrong timetable, cancellation and terminal-message handling.
- Go gateway tests exercise HTTP 202 without an implicit success/rejection,
  rejection of other HTTP statuses, exact native acknowledgment relay and
  player ownership. Driver tests preserve completed evaluation and rebase
  successive trips only after confirmation.
- The Windows x86 updater remains limited to Setup and PeDePeAdapter; existing
  host and player manifest compatibility is preserved.

The corrected companion has passed local reproduction and validation. A
complete post-update BCS/openOMSI trip on the user's Windows system still
needs confirmation.
