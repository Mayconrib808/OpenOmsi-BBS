## openOMSI BBS Bridge v1.1.3 — experimental

Download **OpenOmsi + BBS 1.1.3.zip** under Assets. This is the complete Windows package, with **Setup.exe**, all four source-built bridge components, the automatically installed 32-bit helper, offline tutorial, source, credits and licences. The GitHub-generated "Source code" archives do not contain ready-to-run executables.

### Requirements and installation

Install OMSI 2, BCS/BBS and **openOMSI 0.2.0 Windows x64** separately. Extract the entire bridge ZIP to a permanent folder, run **Setup.exe**, configure both paths and choose **2 — Activate / update**. No separate helper download, Go or Python installation is required.

Leave **“Start OMSI faster” unchecked** in BCS/BBS and disable real-time clock synchronisation in openOMSI. At the final stop: **F9 → wait at least two seconds → finish in BCS/BBS while openOMSI remains open**. Setup option **3** restores launching original OMSI.

### Validation

Linux and Windows source checks, four Windows builds, package integrity and native Windows synthetic DLL tests passed. Release publication also checks that all four executable hashes match the v1.1.3 package tested by Mayconrib808.

A live Windows trip on **2026-10-06** used **Carrão City**, line **2201**, tour **02**, departure **09:20**, **Divisa de Ferraz → CPTM Guaianazes**, with **Caio Apache VIP I OF 1721 manual**. The original `bbs.dll` loaded; timetable alignment, six stops, eight tickets totalling **25.90**, saved evaluation and the BCS completion handshake were observed. openOMSI then exited normally. See [the validation record](https://github.com/Mayconrib808/OpenOmsi-BBS/blob/v1.1.3/docs/VALIDATION.md).

This is an **experimental prerelease**. The live result covers that map/bus combination; other maps, buses, updates and complete evaluation/payment parity still need testing. The existing Berlin-Spandau loading problem remains documented. This independent project does not claim official PeDePe or openOMSI support.

## Português do Brasil

Baixe **OpenOmsi + BBS 1.1.3.zip** em Assets. O ZIP contém **Setup.exe**, todos os componentes, auxiliar automático, tutorial offline, código-fonte, créditos e licenças. Os arquivos automáticos "Source code" do GitHub não contêm os executáveis prontos.

Extraia tudo em uma pasta fixa, abra **Setup.exe**, configure os caminhos e escolha **2 — Ativar / atualizar**. Você precisa ter OMSI 2, BCS/BBS e **openOMSI 0.2.0 x64** instalados. O auxiliar já vem incluído; não é necessário instalar Go ou Python.

No BCS/BBS, deixe **“Iniciar o OMSI mais depressa” desmarcado** e desative a sincronização com o relógio real no openOMSI. No ponto final: **F9 → aguarde pelo menos dois segundos → finalize no BCS/BBS com o openOMSI aberto**. A opção **3** devolve a inicialização ao OMSI original.

Os testes Linux/Windows passaram, e uma viagem real em **Carrão City, linha 2201, tour 02, às 09:20**, com **Caio Apache VIP I OF 1721 manual**, confirmou carregamento da `bbs.dll`, horário alinhado, seis paradas, oito bilhetes no valor de **25,90**, envio da avaliação e encerramento normal após a conclusão pelo BCS.

Versão **experimental**, validada nessa combinação de mapa e ônibus. O problema de carregamento de Berlin-Spandau continua registrado. Outros cenários e equivalência completa da avaliação/pagamento ainda precisam de testes.
