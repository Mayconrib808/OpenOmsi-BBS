# Bridge 2.2.0.8 — Hotfix 1

Native base: official openOMSI v0.3.41, cumulative Coop12/13/14, P15.

The recorded 89-person boarding burst used the same message bucket as commands and INFO. Passenger descriptions, boarding/discovery control, and passenger world frames now have separate bounded per-peer budgets. Descriptions are paced at eight per 100 ms world update and refreshed every five seconds to recover from UDP loss.

The client creates at most twelve newly visible mirrored passengers per render frame, retains the rest for subsequent frames, and flushes body operations once per nonempty spawn batch. Existing people continue updating. Population limits and simulation ownership do not change.

The native hotfix patch is restricted to lan_world.rs, omsi-net/lib.rs and its transport regression tests. Scene/tile loading, timetable/date handling, startup deadlines, cameras, driver handover, skins and the legacy P14 executable remain from the cumulative base. The existing approved Fechou recording and retained HostAgent/CompanyHost are checked against the prior published bundle before distribution.

The Windows workflow runs the real-socket crowd regression, bounded-channel/sender checks, the network library suite, existing Coop13 regressions and the Bridge suite including Carrão City timetable cases. A live two-player session and an actual Carrão City map load require the user's installed assets and are not represented as completed by these automated checks.
