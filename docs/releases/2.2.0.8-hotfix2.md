# 2.2.0.8 Hotfix 2 (2.2.0.8.2)

Fixes HostAgent/CompanyHost terminating a live session after two stale clock samples during recoverable vehicle or scenery loading. Clock correction now has a continuous three-minute recovery window, reset only by confirmed synchronization. Status transport failures use the same bounded recovery window. Redundant clock commands stop while status is already within its minute-resolution tolerance. Calendar ambiguity and persistent synchronization failures still terminate safely.

Reproduction: SP Noroeste V2, player GranViale_O500U.bus join. Server logged a 53,348 ms placeholder frame, then the supervisor stopped the session with “accepted clock commands but did not synchronize”. Client tunnel reset/530 and timeout followed. The exact origin of the slow placeholder frame remains unprofiled; this release fixes supervision, not vehicle load duration.

Rebuilt HostAgent.exe and CompanyHost.exe are included in both the signed seven-component updater and personal-host distribution. The native Coop14 Hotfix1 game and dedicated server, audio, maps, timetable, driver transfer, cameras, passenger fixes, protocol 15 and legacy protocol 14 binaries are preserved. No native game version was renamed or rebuilt.

Validation: complete Go tests and vet on Windows and Linux; stale-clock 53-second join replay, recovery reset, persistent-failure deadline, midnight and calendar safety. Publication verifies unchanged gameplay asset hashes and that updated hosts appear in both installation paths. Real two-player gameplay on user maps is not exercised by CI.
