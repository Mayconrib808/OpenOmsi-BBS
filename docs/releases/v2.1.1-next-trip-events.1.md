# Next-trip LAN event correction

The automatic updater was applied and the BCS log observer correctly exposed the accepted new shift, line and tour. The native companion then timed out in multiplayer: it declared `lan_message` as a bare global function, but the openOMSI plugin runtime delivers events to handlers registered with `omsi.on(event, fn)` or to `on_<event>` globals. As a result the companion did not process the host's `ready` reply and never requested the new duty.

The companion now registers `lan_message` explicitly. It accepts replies only from the host, and confirms only the active request after the native client reports the matching timetable. Native handshake, request and acknowledgment progress are logged; timeouts identify the missing stage. The player adapter identifies this build as `native-live-next-trip-2`.

The Lua harness now delivers real events through registered handlers instead of directly calling a function that the game never invoked. This reproduces the previous readiness failure and covers the repaired multiplayer handoff, ignored foreign/stale replies, missing host, native rejection, and the existing local duty and evaluation checks. The existing self-contained `Atualizar-Bridge.exe` installs the revised player adapter automatically and recognizes the previously prepared BCS archive. HostAgent remains `2.1.1-host.2`.

Validation: actual Lua 5.4 event harness, targeted Go live-trip tests, Windows x86 build and vet. Full confirmation in the user's BCS/openOMSI session remains necessary.
