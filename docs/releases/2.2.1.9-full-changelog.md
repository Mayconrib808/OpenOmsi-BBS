# OpenOMSI BCS Bridge 2.2.1.9

## Major release — introducing the modified openOMSI Coop game!

**The complete modified openOMSI game is now included with the OpenOMSI BCS Bridge, not only the BCS adapter.** This is a substantial cumulative update over 2.1.9: you get a custom cooperative multiplayer simulator with new features for drivers, conductors and passengers, alongside the Bridge, Setup, HostAgent/CompanyHost, a compatible P15 dedicated server and a legacy P14 server.

**Native game:** modified **openOMSI 0.3.45 Coop15 (protocol 15)**. This is a community-modified game build, **not an official release from the original openOMSI developers**. The ZIP contains changes through 2.2.1.9 Hotfix 2, plus the BCS localization and Setup corrections.

## Part I — Evolution of the Bridge since 2.1.9 (BCS, PeDePe, multiplayer hosts and Setup)

**The Bridge has received major independent improvements — this is not just an openOMSI game update.** The following features and fixes belong to the Bridge integration, PeDePe adapter, Setup, HostAgent, CompanyHost and company network gateway. They are cumulative changes since the original **2.1.9** release.

### 1. Much broader BCS compatibility and safer integration

- Upgraded compatibility beyond the original **BCS 5.0.2.0**, including the inspected **5.0.3.0** update and its renamed internal data-state owner.
- Removed the former **BCS-version / complete JAR-hash restriction**. A resource-only change or different JAR packaging no longer blocks **Save and activate** unnecessarily.
- Changed the Next Trip observer to identify a compatible installed BCS state interface rather than relying exclusively on the exact release hash or a fixed obfuscated class name.
- If that interface actually changes, Setup can still activate the Bridge while recording that the optional logger extension could not be installed; it does not blindly alter unfamiliar vendor code.
- Fixed a BCS internal API change that made the older Next Trip observer inspect a **vehicle damage** state by mistake, hiding valid next-trip selections.
- Setup/updater repairs the previously installed observer while BCS is closed and creates a recoverable backup of the user's existing local JAR. **No proprietary BCS JAR is distributed.**
- Preserves BCS's native **LAN host / LAN join** choices instead of accidentally injecting a second company session. For Bridge-managed company multiplayer, the corresponding BCS standalone choice remains available.
- **NEW — localized driver names:** the PeDePe adapter now accepts both **Bus Company Simulator** and **Simulador de Companhia de Autobuses** without destroying or renaming the original BCS driver profile. Other localized names remain unverified.

### 2. Next Trip, timetables, IBIS and destination displays

- Improved **Next Trip** continuation so a new BCS duty can be selected in supported sessions **without restarting openOMSI**.
- Added safer recognition of a fresh BCS shift, route, selected map and journey while retaining the original completed trip's evaluation data.
- The Bridge requests the next duty through the **authenticated host-controlled multiplayer path** and waits for dispatch/acknowledgment instead of treating an unsupported native request as accepted.
- Improved timetable matching and preservation of BCS departure times when switching to a follow-on trip.
- The Bridge waits for the native bus IBIS and verifies the **actual HOF destination index**; sending a destination request is no longer considered proof that the displayed destination changed.
- With one unambiguous HOF match, it can request **up to two corrections while the bus is stopped** and then verify the result.
- Missing/ambiguous HOF destinations or unresponsive destination displays generate diagnostic warnings instead of silently blocking the next BCS duty. Manual corrections can also be detected later.
- Driver handover keeps the duty associated with the **original BCS owner**, even while another connected player is operating the physical bus.

### 3. Fuel synchronization and manual bus startup

- Added **Start the bus automatically** in Setup, enabled by default to preserve existing behavior.
- Disable this option to start the engine and configure the IBIS manually. The BCS trip, timetable, map, vehicle, position, fuel and damage information remain available.
- This is a **player-specific preference** and is preserved across supported package moves and updates.
- Corrected priority of the **real fuel value supplied by BCS** so a bus does not always begin with 100% fuel.
- BCS values such as **zero litres** are intentional valid values and are no longer automatically overridden by a full tank.
- Fixed the invalid native **--keep-fuel** argument that could prevent openOMSI from starting. The adapter uses supported startup/variable arguments instead.
- Improved launch diagnostics for fuel and selected journey information when investigating start-up mismatches.

### 4. HostAgent/CompanyHost connection reliability

- Improved the existing **automatic company hosting** workflow: players select a BCS trip, the Bridge requests the correct company map, HostAgent opens it on demand and publishes the current validated session address.
- Fixed premature connection failure while a requested map was still loading, even though HostAgent had already received and started the map request.
- Profile queries, repeatable map-start requests and session polling retry temporary network errors and HTTP **408, 429, 500, 502, 503 and 504**, for up to **30 seconds per request** within the session's overall startup deadline.
- Authentication failures, invalid JSON, unexpected redirects, mismatched company identity and disabled/offline/error states remain actual failures. Temporary retry logic does not bypass them.
- The Bridge refuses to rely on an obsolete cached server tunnel: it uses the **currently published address** for the company and requires the correct identity.
- Improved diagnostics with more useful transport errors, including **Portuguese, English and German** messages, without exposing private invitation URLs.
- Improved identity/reconnection handling and display of the actual current Bridge version in HostAgent.
- Company profiles, invites, saved maps, external server choices and personal settings are preserved through supported upgrades.

### 5. Server Status, monitoring and one-click joining

- Added a **Server Status light** in Setup, showing ready/unavailable states with a manual refresh button.
- Checks on opening and refreshes about **every five seconds**, without blocking the Setup UI.
- A company map that is configured and ready to start **on demand** can report as available even when its dedicated game process is not yet running.
- Offline agents, unavailable directory checks, disabled maps and invalid configurations show warnings instead of false online indications.
- Read-only status checks do not wake maps or change server settings.
- Displays currently online maps and their **real player connection addresses**, with a copy button for supported ready sessions.
- Added **pagination** for more than three active maps; offline/expired/starting addresses are not offered as ready-to-join links.
- The copied address is the **game connection endpoint**, not a private company invitation, management password or administrative token.
- Setup can display company-profile monitoring information on a player computer without local HostAgent configuration.

### 6. Native file transfer, protocol support and dynamic servers

- Expanded compatibility across the native openOMSI **protocol 6, 7, 14 and 15** generations, while requiring **matching client/server protocols** for every individual session.
- Fixed the **Windows 10054 / bus upload** problem introduced by newer native openOMSI builds: older company servers now answer that uploads are disabled instead of treating the separate file channel as a lost gameplay connection.
- On supported native **openOMSI 0.3.38+** servers, HostAgent detects transfer capability and routes **bus models and liveries** through the existing company address.
- The native transfer implementation handles session authentication, hashes, resumable transfer and its own content checks; the Bridge's gateway keeps file traffic separate from gameplay player slots.
- Original bus paths/model identifiers are preserved, while local substitutes remain available where actual bus transfer is unsupported.
- **Map sharing stays disabled**; players still need their installed map and dependencies.
- Added and maintained separate **P14 and P15 dynamic dedicated server** packages. Managed host selections can migrate with backup when appropriate; independently selected custom servers are respected.
- Improved startup and world-ready status reporting during initial simulation, including cold traffic/passenger loading.

### 7. Administrative clock changes and preserving full HostAgent controls

- Fixed HostAgent/CompanyHost stopping a recoverable session after only two stale clock samples during slow vehicle or scenery loading.
- Added a **bounded recovery period of approximately three minutes** for clock/status synchronization; persistent failures and unsafe calendar conditions still stop safely.
- Added the opt-in HostAgent setting **Allow admin clock changes after synchronization**, **off by default**.
- After the initial clock synchronization against the BCS company reference, authenticated administrators can set an exact **HH:MM:SS** and request up to **32× time speed**, if enabled.
- The host monitor no longer immediately overwrites permitted admin clock adjustments; initial company date/time validation is still maintained.
- Preserved and checked complete P15 controls for **proximity voice, radio, voice range, public-server listing, hardware identification, map settings and admin passwords**.
- Corrected a temporary host-update regression that lost P15 UI controls; the full approved HostAgent and CompanyHost functionality is retained in this release.
- Improved map switching, save/reopen and preservation of unrelated host preferences in native Windows interface checks.

### 8. Setup, signed updates, backups and recovery

- Improved **Check for updates / Buscar atualizações** and the cumulative updater rather than requiring installation of every intermediate version.
- Added repair of **incomplete or older Bridge installations**: a verified update can restore the required Bridge executables, recreate missing directories and refresh the runtime integrity inventory.
- Optional documentation missing or modified no longer blocks the Bridge from being recovered. An inability to prepare a moved BCS installation does not need to undo an otherwise valid Bridge update.
- Preserved download signature verification, SHA-256 checks and installed-file verification where applicable.
- Fixed **Setup-to-updater handoff**, including stale/recycled process IDs, alternate paths to the same Setup executable, a Setup process remaining invisible after its window closes, and waiting for the correct process to exit.
- Active game, host or setup operations remain protected; updater logic does not simply force-kill arbitrary matching processes.
- Added the bundled modified Coop executable and the Setup option to select the **included game**; supported update paths can download checked Coop package chunks with progress.
- Added **Backup / Restore backup** of supported modified Coop installations, with file checks and preservation of installed maps and personal configuration.
- **Fixed Update Now** reading the OMSI 2 directory currently entered in the Setup field **before** the user has saved or activated the form.
- This fix applies to Setup's button; it is **not** a claim that every old standalone updater's automatic BCS/Bridge path detection is fixed.
- The current Release offers a **full standalone Windows ZIP** containing the Bridge, modified openOMSI game, dedicated servers, source archives, notices and checksums for manual installation.

**Bridge testing note:** These integration improvements are documented in the project's changelogs and automated build checks. A complete live two-PC BCS trip and all conductor/transfer scenarios are still pending validation for this exact ZIP.


## Part II — Modified openOMSI Coop (gameplay changes)

## All major changes to the modified openOMSI since Bridge 2.1.9

### 1. Shared buses, driver handover and conductor gameplay

- **Driver handover:** transfer driving of an existing bus to another player. The visitor takes control of the real local vehicle physics, scripts and controls while the original owner keeps the BCS trip and evaluation association.
- The visiting driver's previous bus is hidden/suspended during the handover, then restored when control returns. Only the authorized current driver may return the wheel voluntarily.
- **Cooperative conductor / ticket collector:** another person can help with tickets, the cash register and passenger payments.
- **Physical money synchronization:** coins and banknotes become visible to the authorized conductor; fare payments, ticket selection and change share the same original cash desk.
- **Collect cash with Shift+T, mouse or the Collect money control.** Acknowledgments prevent two players from collecting a single payment twice.
- Improved passenger ticket dispenser interaction, correct ticket names/prices and click handling when the cooperative UI is open.
- Players can move around the cabin, sit, stand and assist without becoming a second simulated bus.
- Fixed invisible or duplicated vehicles, unusable controls, accidental driver-seat reclamation, wrong character positions and handover-related passenger disappearance.
- On returning the vehicle, the former driver appears at the **bus's current location** rather than the earlier handover position.
- The original simulation's passenger cabin and passenger count remain available after the change; occupancy is reflected in the HUD.
- Improved F1/F4 camera views, vehicle interactions, authority changes, disconnection recovery and command acknowledgments.

### 2. Player characters, skins and walking outside the bus

- Added **Alt → Cooperative → Choose character / skin**, with search, pages and selection of installed .hum characters.
- Character choice persists and is synchronized to other players across walking, role changes, switching vehicles and respawning.
- Added/improved **Start on foot**, allowing players to appear to others without first driving a bus.
- Improved walking, sitting and player positioning inside shared buses.
- Fixed character render identity changes during network interpolation.
- Improved vehicle repaint/skin preservation and display for remote players.
- Supported native bus/livery file transfers when client and server versions support them; keeps substitute models when needed. Maps and dependencies remain locally installed.

### 3. Passenger signals and realistic bus-stop behavior

- Passengers can recognize an approaching bus that matches their **line and destination** and signal for it.
- Improved the signal's direction relative to the bus, limited detection distance (approximately **60 metres** in the implemented logic) and eligibility for each waiting passenger.
- Refined a Brazilian-style gesture with extended arm, relaxed hand, correct finger, moving palm and **wrist motions with short pauses**.
- Added smoother head, neck and torso tracking as passengers watch their approaching bus, with bounded rotations to avoid extreme twists.
- Corrected backwards-pointing arms, unnatural elbows, hand movements and excessive neck turning.
- Full buses receive only a short first request; passengers stop repeating the signal until there is room.
- Improved walking and ground contact at stops, including less vertical bobbing.
- Improved synchronization of passenger intent and reduced frame/network overload when a large crowd boards.

### 4. Rain, umbrellas, roofs and water droplets

- Waiting passengers can **open umbrellas in rain**, including passengers spawned while rain is already active.
- Added opening, folding, carrying and reopening animations; the umbrella lowers when boarding.
- Umbrellas can close under detected shelters, including certain glass or thin roofs, and reopen after leaving cover.
- Added raindrops and water flow over wet umbrella surfaces, plus water dripping from the edges and tip.
- Improved canopy/arm/pole rotation as umbrellas fold, including droplets that stay visible while the umbrella is still wet.
- Fixed droplets disappearing the instant the canopy starts closing.
- Moved part of sky/weather processing to background preparation to reduce some weather-related stuttering.

### 5. Connecting passengers and ticket controls

- Added an **experimental passenger transfer system**: eligible passengers alight, walk to another loaded stop or stay at the **same stop**, then wait for a different valid bus route.
- Passengers keep their identity and do not immediately signal or reboard the bus they just left.
- Uses available stop destinations and timetable information to choose possible connections.
- Added a **transfer probability** control from **0% to 100%, default 20%**, adjustable in lobby/gameplay. It is a per-simulation preference, not a global rate imposed on every dedicated-server client.
- Improved synchronization/return of transferring passenger state between simulation authorities in later builds, although real two-PC journeys still need testing.
- Added an optional **ticket-purchase probability** control from **0% to 100%** (disabled by default). It affects eligible new boardings where ticket-selling equipment is available.
- Improved ticket selection, display prices and handling of actual fare transactions.

### 6. AI traffic, horns and sound

- Improved AI bus greeting events with **two short horn taps**, a defined pause, fades and better audio envelopes.
- Improved horn playback on buses whose recorded sounds or pitch differ, including short loops.
- Added appropriate distance and cabin filtering; reduced flooding from distant/repeated sound packets.
- Preserved the custom **door-closing signal** audio and existing sounds.

### 7. Floating camera editor and gameplay menus

- Added **Alt → Camera**, a floating editor on top of the cab view.
- Modify camera position, height, look direction, field of view and **mirror settings in real time**.
- Save per-bus preferences, reset or close with Alt/Esc.
- Added PT-BR, English and German labels for the camera editor.
- Improved player camera behavior after changing seats, walking inside a bus or taking/returning control.
- Refined cooperative action menus and bus-click forwarding.

### 8. Game/network performance and server changes

- Prioritized critical driving/control data over bulk passenger/world updates during busy sessions.
- Paced passenger descriptions and remote passenger rendering/spawns across frames rather than doing everything at once.
- Improved network backpressure, bus interpolation, remote camera/panel refresh and synchronization during driver handovers.
- Improved world loading around **buses and on-foot players**, not just the host vehicle.
- Updated the modified **native P15 dynamic dedicated server** with the game, while keeping a separate older **P14** server for compatible sessions.
- Added native exact time adjustment (**HH:MM:SS**) and up to **32×** clock speed for authenticated server administrators when permitted.
- Ported cumulative cooperative features through upstream openOMSI **0.3.38, 0.3.39, 0.3.40, 0.3.41, 0.3.43, 0.3.44 and 0.3.45**. The distributed game executable and P15 server are actual modified builds, not merely renamed stock versions.

## Installation and updating

1. Download **`OpenOMSI_BCS_Bridge_2.2.1.9.zip`** from the **Assets** section below (not GitHub's autogenerated source archive).
2. Extract the **whole ZIP** to a permanent folder **outside the OMSI 2 game folder**.
3. Close BCS, OMSI 2, openOMSI and the Bridge/HostAgent processes.
4. Open `Setup.exe`, select your OMSI 2 installation and the bundled openOMSI Coop executable, then save/activate.
5. In BCS, choose **OpenOMSI (Beta)** and point to the included `PeDePeAdapter/openomsi.exe`.
6. When upgrading, back up your existing Bridge installation and preserve any personal `app/bridge.ini`, company settings, invitations, custom maps and host data.

**This is a full cumulative package**; you do not need to install each intermediate 2.1.9/2.2.x version separately. For cooperative sessions, update all players and the P15 company host to compatible builds and start a new session.

## Compatibility and testing

- Requires **Windows, a legitimate OMSI 2 installation and Bus Company Simulator**. Commercial games, paid addons and maps are **not included**.
- The current bundled modified openOMSI is based on **0.3.45 Coop15 / protocol 15**. Legacy P14 remains separate; clients and servers cannot mix incompatible protocols.
- The core Windows binaries and focused automated tests passed. However, **a full real two-PC BCS trip with this exact localized distribution has not been verified**, and some multiplayer/AI/animation behavior can vary with installed maps and vehicles.
- This is an **experimental community project**. For issues, include relevant logs and the affected game/BCS versions.
